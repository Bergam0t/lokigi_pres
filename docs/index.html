What is location optimization?

Where should I put my healthcare resources?

  • If I’m closing one service, which should it be?
  • If I’m adding a new site to an existing service, which of these 5 possible places should I put it?
  • If I’m spinning up a totally new service, how should I distribute my sites?

The Current (Python) Landscape

spopt

Pros

  • Part of a wider ecosystem (pysal - Python Spatial Analysis Library)
  • 350+ github stars
  • 24 contributors (i.e. pretty robust)
  • Quite a lot of documentation…
  • … but the documentation is (imo) quite confusing
  • Not healthcare or UK focussed
  • Linear optimization returns a single option by default
  • Need to manually create your own output plots

HSMA and Open Source Exeter MSc content

Pros

  • Returns multiple options
  • Written with UK healthcare in mind

Cons

  • Requires manual copying and adapting of code
  • Still need to manually create your own plots
  • Risk of more errors due to unreviewed code without automated tests
  • Still lots of repetition across organisations

lokigi

Lokigi is a brand new package building on the HSMA and Exeter approach.

It aims to provide an easy-to-use workflow to simplify and speed up location optimization work.

lokigi


The goal is to make it work optimally for
**UK healthcare contexts**


If it works for other contexts, it’s a bonus - not the other way around.

Simple Problem Formulation

At its core, you only need a travel matrix.

from_id Cumberland Centre (Plymouth) Dawlish Community Hospital Derriford Hospital (UTC) Exmouth Minor Injury Unit
East Devon 001A 75.0 44.0 70.0 38.0
East Devon 001B 71.0 40.0 66.0 33.0

Simple Problem Formulation

Setting up your problem is easy.

from lokigi.site import SiteProblem

problem = SiteProblem()

problem.add_travel_matrix(
    travel_matrix_df="path/to/devon_miu_travel_matrix.csv",
    source_col="from_id",
    unit="minutes",
    )


And you can solve it with a single command.

solution = problem.solve(p=4)

(as it assumes the columns in your travel matrix = your potential sites)

Simple Problem Formulation

By default, lokigi will

  • brute force the solution
  • assume you want to solve a p-median problem (minimize travel time - weighted by demand if you provide that)

It also supports

  • p-center (minimizing max travel time)
  • the Maximal Covering Location Problem (given x sites, how to we maximise people within y distance?)

Adding Demand

And optionally we can add demand data too if we want to weight our solution.

problem.add_demand(

Solving with Demand and Coverage Thresholds

We simply solve again!

This time we’ll also pass in how many regions we want to be within a given travel time.

solution = problem.solve(p=4, threshold_for_coverage=20)

(enhancements to this coming soon - i.e. counting based on demand/population, not per-region)

Additional Features - Equity

We recognise that the equity of solutions is important, so there are some early functions to help assess this.

This is again designed to work with easily available government equity data from sources like the ONS geoportal again.

problem.add_equity_data(
    "Index_of_Multiple_Deprivation_(Dec_2015)_Lookup_in_England.csv",
    equity_col="IMD15",
    common_col="LSOA11NM",
    label="Indices of Multiple Deprivation",
    continuous_measure=True,
    reverse=False
    )

solution = problem.solve(p=4, threshold_for_coverage=20)
